This is a local native diagnostic grader, **not the official Docker SWE-bench evaluation**. `preflight.py` clones the exact base commit into clean private `source` and agent tree, and saves the hidden test patch outside both trees. `score_native.py` clones the clean source into a fresh grade directory, applies the test patch and tracked candidate diff, runs pinned tests with an explicit per-repository adapter, and fails closed on missing tests. Both harnesses use the DeepSeek Flash model through the same admission-metered proxy and no external network access inside their separate bubblewrap workspaces. One compute instance, one run at a time. The proxy keeps a $150 external ceiling but does not impose mission step or wall-time caps. The HAIRSPRING and critic mission step/wall/spend caps are opt-in (including delegated child missions); the OpenHands loop likewise has no added mission cap. A HAIRSPRING model-call watchdog fires at 960 seconds, before the proxy's 1020-second absolute exchange deadline measured from reserve admission. The proxy reads the upstream in a separate worker and coordinates all client forwarding and settlement on its own deadline, including stalls before response headers or midway through a response. A late worker cannot send to the client or settle twice. After a real second deadline stall, a separate watchdog now owns the absolute admission deadline and books unknown usage at the full reserve even when the coordinator is blocked in client forwarding; it force-closes the available upstream and client sockets without waiting for the coordinator. The coordinator and watchdog use a shared per-request settlement ID under the ledger file lock, not a coordinator-held Python lock; usage is published through one immutable snapshot assignment. This watchdog design is offline-tested only, not proven against a paid provider. Either deadline is a transport failure (the HAIRSPRING watchdog returns a provider error, not a fake model completion), never a solved or unresolved *native grade*: proxy settlement books observed usage or the full conservative reserve even on a disconnect; the runner's terminal gate marks nonterminal/error runs unfinished and does not invoke the scorer. A still-reserved ledger halts the sequential batch until settlement or manual audit. This is process safety, not an experiment-level mission cap. DeepSeek currently requires `max_tokens` to be at most 393216; both adapters request this provider maximum, not a lower experimental output cap (https://api-docs.deepseek.com/api/create-chat-completion and https://api-docs.deepseek.com/quick_start/pricing, checked 2026-09-27). Omitting it would use DeepSeek's lower 8K/64K defaults. A task is correctly solved only with terminal run evidence plus native grade. OpenHands steps count distinct LLM response IDs from agent ActionEvent and MessageEvent, so a response with no tool action still counts as a step; parallel actions in one response count once. Its FINISHED status with zero AgentErrorEvent/ConversationErrorEvent gates native grading; ERROR, STUCK, and error-bearing FINISHED runs remain unfinished. All records, traces, patches, grades, and accounting should be preserved. Do not report cost in the comparison table; use solved, steps, and wall time. This experiment is exploratory and cannot support a state-of-the-art claim from 15 instances.
