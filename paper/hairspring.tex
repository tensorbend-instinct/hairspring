\begin{abstract}
Language models can use tools, revise artifacts, and run for long periods. The unresolved design question is who decides what counts. If the same model proposes the work and declares it correct, a fluent failure can cross the system boundary as success. \system{} moves that authority into a replayable substrate. Executable checks close missions. A critic in a fresh context attempts to refute the submitted artifact. A single writer records canonical, hash-linked events. World and memory services admit validated state. A pinned scorer promotes policy changes only after held-out trials. On a matched ten-task SWE-bench-Live subset, \system{} resolved 9 tasks and SWE-agent resolved 3 with the same model family and host-side grading. \system{} used fewer agent steps, more wall time, and more provider-reported cost. This is a bounded harness result, not a general leaderboard claim. It supports a narrower point: the common think--act--observe loop is not the differentiator. Authority is.
\end{abstract}

\section{Introduction}
Agent harnesses commonly wrap a language model in the same control loop: provide a goal, expose tools, append observations, and continue until the model submits an answer. The loop is useful. It is also incomplete. It says how work proceeds, but not who may declare the work correct, which effects become shared state, how a crashed mission resumes, or what evidence can replace the current policy.

These decisions matter because model confidence is not an execution boundary. A model can submit a plausible answer after running the wrong test, repair a symptom while preserving the defect, or repeat a failed action because the environment never proved that success was possible. A longer context does not fix this class of error. It gives the same component more history while leaving its authority unchanged.

\system{} separates work from judgment. The model proposes actions and artifacts. Mechanisms outside the working context decide whether an effect enters durable state, whether the mission closes, and whether a policy change replaces the incumbent. The event record connects those mechanisms. It is operational state rather than a post-hoc transcript: recovery, inspection, memory extraction, accounting, and outer-loop scoring read the same history.

\paragraph{Contributions.} This paper makes four contributions.
\begin{enumerate}
\item It defines an authority architecture for long-running agents: checker, critic, event record, world service, memory service, and scorer have distinct powers.
\item It implements the architecture as a 14-crate Rust workspace with an installed terminal path, typed plugin protocol, process confinement, replay, bounded child agents, and policy-level self-improvement.
\item It reports a matched ten-task comparison against SWE-agent, including steps, wall time, cost, failures, and the limits of the comparison.
\item It turns failures at subsystem seams into an evaluation method that distinguishes local mechanism tests, installed-path tests, live artifact trials, and matched external evaluation.
\end{enumerate}

\section{Design problem: the model cannot be its own authority}
A useful harness must answer five questions that the inner loop cannot settle by assertion.

\paragraph{Did the requested artifact work?} The answer belongs to executable checks that run against the judged workspace, followed by an independent attempt to find a blocking defect.

\paragraph{What happened before a crash?} The answer belongs to a durable event stream with explicit ordering, payload identity, and recovery semantics. A reconstructed prompt is not enough because it can omit tool state, counters, costs, or partial effects.

\paragraph{Which effects become shared truth?} The answer belongs to a validation boundary. Child agents may propose updates, but proposals do not become world state merely because a model wrote them.

\paragraph{Which memories deserve reuse?} The answer belongs to records with provenance and observable reuse signals. Retrieval relevance is different from correctness; the system preserves that distinction.

\paragraph{Which change improves the harness?} The answer belongs to repeated trials under a pinned scorer. A candidate cannot choose the test, grade the result, and promote itself.

The architecture follows from these answers. The model remains free to search, edit, call tools, delegate, and revise. It cannot write a passing verdict, append directly to the canonical log, bypass world validation, or publish a promotion record without the scorer path.

\section{System overview}
A mission binds a goal to a project root, provider configuration, tool registry, checks, budgets, and a durable run directory. The worker calls typed tools through a newline-delimited JSON protocol. The loop records requests and results as events. Large payloads are stored by content hash. The worker submits an artifact together with the checks that define success. The checker restores the judged workspace, runs those checks, and invokes the critic. A failure returns evidence for repair. A check pass with no blocking critic finding records a verified outcome.

Five planes surround this lifecycle.
\begin{description}
\item[Log plane.] Canonical events, one writer, segmented persistence, torn-tail recovery, and replay.
\item[World plane.] Validated proposals, shared artifacts, and observable reuse across agents.
\item[Memory plane.] Extracted records, provenance, retrieval, and citation feedback.
\item[Accounting plane.] Model calls, tool work, child-agent work, limits, and billed cost.
\item[Evolution plane.] Candidate policies, pinned assays, canaries, promotion, and rollback.
\end{description}

This organization is model-agnostic. Providers are configuration. The authority boundaries do not depend on a particular model family, and a model change is logged as an infrastructure change rather than silently credited to policy fitness.

\section{Mission execution}
\subsection{Typed tools and a generated surface}
Tools run as processes behind a typed protocol. The kernel registers capabilities and generates the mission surface from that registry. This avoids maintaining one tool list in the prompt and another in execution code. Requests and results retain the registered tool name, arguments, timing, outcome, and payload references in the event stream.

The edit path uses anchored or patch-based mutations rather than unconstrained file replacement. Terminal execution occurs inside a platform confinement layer. On Linux, the runner uses bubblewrap; on macOS, it emits a Seatbelt profile. Startup fails when the required confinement mechanism is unavailable. The project and required caches remain writable while system paths remain read-only.

\subsection{Submission is a transaction}
A submission carries the answer and its declared checks together. The checker judges a restored workspace, not whichever transient directory happens to be current. This ordering closes a race found in an earlier path where answer text could become visible before the final check declaration was persisted. The regression test reproduces the original multi-step failure rather than testing only the repaired function.

\subsection{The critic can block but cannot approve}
The critic receives the goal and submitted artifact in a fresh context without the worker's rationale. Its job is to identify a grounded blocking defect. In the production path it runs under a read-only operating-system identity. An abnormal critic exit fails closed. A critic report can return work for repair; it cannot by itself turn failed executable checks into a pass.

Verdict records distinguish verified work from capped retries or verifier malfunction. This distinction prevents an operational limit from being rendered as successful judgment.

\section{The event record}
A transcript records conversation. A run record must reconstruct action. \system{} uses typed, canonical events, content-addressed payloads, segmented streams, and a single append authority. Recovery reads a consistent prefix, detects torn tails, and restores mission state. Plugins return effects to the loop rather than appending events directly.

The constraint changes the semantics of resume. A resumed mission carries the previous transcript, tool results, counters, ledger, and billed cost. It does not start a cosmetically similar mission under a new identity. Mid-run steering, provider changes, child-agent work, and scoring evidence remain events in the same history.

\evidence{Storage tests inject torn tails, duplicate clock values, corrupt registry markers, dead plugins, interrupted migrations, and replay after promotion. The relevant proofs live in the crate test suites at the evaluated source revision.}

\section{Shared work without shared authority}
\subsection{Bounded child agents}
A parent can start asynchronous child missions with explicit step limits. Each child writes to its own stream under the parent's log root, books its work to the parent, and joins before mission close. Child agents cannot recursively delegate. The depth boundary is enforced by the spawned tool surface, not by a natural-language request.

\subsection{World proposals}
Agents submit proposed effects to the world service. Validation separates a model's report from shared state. Accepted artifacts can be discovered by another child without a direct message between them. Reuse remains observable in the world record.

\subsection{Memory with provenance}
The memory service stores extracted records in a global knowledge base. A served record that a later mission cites receives positive feedback; a served record that the mission ignores receives negative feedback. This is a reuse signal, not a truth score. The original source and mission identity remain attached to the record.

The system has end-to-end tests for writes, recall, and cross-child reuse. A broader behavioral question remains open: whether a capable live model selects the right record as the knowledge base grows.

\section{Policy-level self-improvement}
The inner loop repairs a task artifact. The outer loop changes harness policy. A proposer receives durable prior policy, traces, scores, reflections, and frontier state. It emits a candidate. Candidate and parent run on held-out tasks under a scorer pin established before mutation. Canaries detect scorer drift. Promotion records retain candidate and parent hashes, assay conditions, traces, scores, decision, and reason.

Two observed promotions preserved equal pass counts while reducing total steps from 94 to 52 and then from 76 to 41. These were small, two-task assays. They show that the promotion path can produce and install a winner. They do not estimate a population-level improvement rate. The current system changes prompts and policy artifacts; it does not yet author and safely promote changes to its own Rust implementation.

\section{Evaluation method}
The evaluation separates four kinds of evidence. Source and unit tests establish that a mechanism exists and preserves local invariants. Installed-path seam tests establish that the terminal, registry, sandbox, checker, and rendered state connect the mechanism to a real mission. Live artifact trials establish that a real model can produce and pass an independently judged artifact. Matched external evaluations compare harness outcomes under a shared judge.

\begin{figure}[t]
\centering\includegraphics[width=.96\linewidth]{figures/evidence-layers.pdf}
\caption{The evidence ladder used in this paper. A large unit suite does not substitute for an installed-path result, and a live result does not by itself establish a general benchmark claim.}

The principal comparison uses ten SWE-bench-Live tasks with the same model family and host-side fail-to-pass checks. Each system operated through its native interface. Raw records identify task, submission status, outcome, steps, wall time, and cost. The comparison is a curated subset, not a leaderboard sample. There are no repeated seeds or confidence intervals.

\section{Comparison with SWE-agent}
SWE-agent is the reproducible incumbent for this study because it provides a public implementation, a defined agent--computer interface, and an executable run path. The systems solve different boundary problems. SWE-agent focuses the model's interaction with a computer. \system{} adds in-run judgment, replay, shared-state authority, and outer-loop policy evaluation.

\begin{table}[htbp]
\small

The trade is visible. \system{} spends more time and money to judge and repair during the run. SWE-agent remains simpler and cheaper when an external evaluator already supplies the authority and replay, memory, shared world state, and self-improvement are outside the job.

\section{Failure-driven engineering}
The highest-value defects crossed subsystem boundaries while local tests remained green. Four examples shaped the current test rule.

\paragraph{A dead tool surface.} A capability could exist in a crate while the production terminal never registered it. The fix required a seam test through the real registry and TUI path.

\paragraph{A wrong production mode.} General missions accidentally used an amnesiac benchmark arm. Unit tests for both modes passed; only a live installed-path run exposed the selection error.

\paragraph{Recursive delegation.} The first real delegation test allowed descendants to delegate until the host reached roughly 7,800 processes. The repaired design removes delegation from a child's surface and adds an explicit spawn cap.

\paragraph{An impossible gate.} Missing test dependencies and strict marker settings caused the evaluator to collect zero tests while the agent kept repairing a correct patch. Preflight now proves that the gate can execute before a mission starts.

These failures lead to one rule: a mechanism is not accepted because its crate test passes. Its regression must reproduce how a model reaches it through the installed terminal path, including registry, sandbox, project root, judgment order, and rendered outcome.

\section{Relationship to long-horizon research controllers}
Stellar Colosseum organizes long-form research into strategy exploration, a readiness gate, a section dependency graph, local subproblem solving, and global verification. Its strongest transferable idea is explicit control over when a strategy is mature enough to decompose and where a verifier's finding should return \cite{colosseum}.

\system{} supplies a lower substrate for such a controller: replayable state, executable checks, a fresh critic, bounded children, shared world and memory planes, accounting, and held-out evolution. It does not yet implement Colosseum's research-proof control plane. Missions remain flat. Critic findings return as whole-mission gaps. Candidates are selected or compared rather than constructively synthesized with their objections. No typed section graph localizes a defect to the affected dependency closure.

A research mode can be built above the current boundaries: strategy exploration $\rightarrow$ readiness decision $\rightarrow$ typed dependency graph $\rightarrow$ eligible child solves $\rightarrow$ global verification $\rightarrow$ affected-section repair or renewed exploration. The whole-artifact critic should remain final authority. Fixed tree widths should not become defaults without matched-compute evidence.

\section{Limitations}
\begin{enumerate}
\item The headline comparison contains ten curated tasks. It establishes a difference on that subset, not general software-engineering superiority.
\item Verification is expensive. On the matched subset, \system{} spent about 7.2 times as much as SWE-agent and took substantially longer.
\item The study has no repeated seeds and cannot estimate result variance.
\item Self-improvement changes prompts and policy artifacts, not the Rust implementation.
\item Memory writes, recall, and cross-child reuse are exercised end to end; live-model selection quality at scale is not measured.
\item The research controller is flat. Strategy readiness, typed section dependencies, objection-preserving synthesis, and section-addressed repair remain unimplemented.
\item At the evaluated paper revision, the workspace test suite passed but current pedantic Clippy produced 50 failures. Passing tests do not make a different quality gate pass.
\end{enumerate}

\section{Discussion}
Authority boundaries make failures legible. A failed check is not an answer-quality opinion; it is an execution fact. A critic malfunction is not a pass; it is a machinery state. A useful memory is not shared truth; it is a record with provenance and a reuse signal. A candidate with an attractive explanation is not an improvement; it is an assay input.

This framing does not remove model error. It changes where error can become state. The worker may still choose a poor plan or spend too long on a dead end. The substrate can preserve the evidence, enforce budgets, refuse an invalid close, and route a grounded defect back for repair. Those properties become more important as missions grow longer because recovery and attribution costs rise with the amount of hidden state.

\section{Conclusion}
\system{} treats agency as a problem of authority. The model does the open-ended work. A checker, critic, event record, world service, memory service, and pinned scorer decide what becomes a pass, durable state, shared knowledge, or an installed policy.

On one matched ten-task software-engineering subset, this architecture resolved more tasks than SWE-agent while using fewer worker steps, more money, and more wall time. The result is narrow. The design lesson is broader: a longer loop does not make its own verdict safer. Long-running agents become easier to inspect, recover, and improve when the loop proposes and the substrate decides.

\section{Event and verdict flow}
The following abbreviated trace shows the intended ordering. Field names are illustrative; the executable schema in \code{hs-core} is authoritative.
\begin{verbatim}
mission.opened    { goal, project_root, provider, budgets }
model.requested   { step, context_hash }
model.responded   { usage, billed_cost }
tool.requested    { name, args_hash }
tool.completed    { status, payload_hash }
answer.submitted  { artifact_hash, declared_checks }
checks.completed  { status, evidence_hash }
critic.completed  { refuted, findings_hash }
mission.closed    { outcome: "verified" | "rejected" | "stopped" }
\end{verbatim}

A valid close follows persisted submission and judgment evidence. A replay reconstructs state from the ordered stream and content-addressed payloads. It does not ask the worker to summarize what happened.
