\begin{abstract}
Language models can use tools, revise artifacts, and run for long periods. The unresolved design question is who decides what counts. This paper classifies the five ways current agent harnesses are built --- direct loops, static workflow graphs, role ensembles, search and evolution controllers, and memory-augmented loops --- and shows that all five leave some part of mission authority inside the model that does the work: declaring results, owning the record, writing shared state, deciding what persists, or promoting self-modifications. \system{} moves those five authorities into a replayable substrate. Executable checks close missions. A critic in a fresh context attempts to refute the submitted artifact. A single writer records canonical, hash-linked events. World and memory services admit validated state with provenance. A pinned scorer promotes policy changes only after held-out trials. On a matched ten-task software-engineering subset with the same model family and host-side grading, \system{} resolved 9 tasks and a representative direct-loop baseline resolved 3. \system{} used fewer worker steps, more wall time, and more provider-reported cost. This is a bounded harness result, not a general leaderboard claim. It supports a narrower point: the think--act--observe loop is a commodity. Authority is the product.
\end{abstract}

\section{Introduction}
Agent harnesses commonly wrap a language model in the same control loop: provide a goal, expose tools, append observations, and continue until the model submits an answer. The loop is useful and well understood \cite{react,sweagent}. It is also incomplete. It says how work proceeds, but not who may declare the work correct, which effects become shared state, how a crashed mission resumes, or what evidence can replace the current policy.

These decisions matter because model confidence is not an execution boundary. A model can submit a plausible answer after running the wrong test, repair a symptom while preserving the defect, or repeat a failed action because the environment never proved that success was possible. A longer context does not fix this class of error. It gives the same component more history while leaving its authority unchanged.

This paper argues that current harnesses differ mostly in how they decorate the loop, while agreeing on the same hidden concession: the model that produces the work keeps some authority over the work. We identify five such authorities --- \emph{close}, \emph{record}, \emph{share}, \emph{remember}, and \emph{improve} --- and show concretely where each approach class leaves them and how each placement fails. \system{} is built on the opposite assignment. The model proposes; mechanisms outside its context decide.

\paragraph{Contributions.} This paper makes four contributions.
\begin{enumerate}
\item A taxonomy of the five current approach classes for agent harnesses, organized by what each class is rather than by product, with the in-model authority and the characteristic failure of each class (Section~2).
\item An authority architecture that moves all five authorities into a replayable substrate: checker, critic, event record, world service, memory service, and pinned scorer have distinct powers the model cannot exercise (Sections~3--8).
\item An implementation as a 14-crate Rust workspace with an installed terminal path, typed plugin protocol, process confinement, replay, bounded child agents, and policy-level self-improvement with observed live promotions (Sections~4--8).
\item A matched ten-task software-engineering comparison against a representative direct-loop baseline under host-side grading, with raw records checked in, and an evaluation method that separates mechanism tests, installed-path tests, live trials, and matched external evaluation (Sections~9--10).
\end{enumerate}

\section{Five ways to build an agent harness}
\label{sec:classes}
Current harnesses fall into five classes. The classes are shapes, not products: many real systems blend two of them, but none escapes the classification, because the classification is about who holds authority.

\begin{figure*}[t]
\centering\includegraphics[width=\textwidth]{figures/fig-classes.pdf}
\caption{The five approach classes, the authorities each leaves inside the model, and where each breaks. Every class can produce impressive demos; the failure column describes what happens on long or adversarial work. The shared root cause motivates the pipeline in Figure~\ref{fig:pipeline}.}
\label{fig:classes}
\end{figure*}

\paragraph{C1. Direct loops.} One model runs a think--act--observe cycle with tool access and submits when it judges the task done \cite{react,sweagent,minisweagent,reflexion}. The class is cheap, transparent, and easy to reproduce. It also concentrates every authority in the model: the model declares the result, owns the only record (its own transcript), writes whatever shared state it can reach, decides what is worth remembering, and judges any change to its own instructions. The characteristic failure is a fluent wrong answer crossing the boundary as a pass: self-evaluation is not independent verification, and language models cannot reliably self-correct reasoning without external signal \cite{selfcorrect}.

\paragraph{C2. Static workflow graphs.} A human authors a graph of steps --- retrieval, generation, checking, branching --- and the system executes it with language-model nodes \cite{workflowblog}. This class wins predictability and auditability for known task shapes. Its failures are structural. The control flow is fixed before the run begins, so off-script situations have no route; decomposition quality is bounded by what the author foresaw; and when a checking node exists, it is the same class of model grading the work, so the judgment problem moves one box over rather than leaving the model. The graph owns no replayable run record of its own; recovery is re-execution.

\paragraph{C3. Role ensembles.} Copies of a model debate, vote, or play planner--worker--judge roles \cite{selfconsistency}. The class adds diversity of phrasing, but not diversity of authority: every participant shares the same weights, training distribution, and blind spots. Correlated errors vote together. Measured failure modes include consensus that manufactures confidence without correctness and errors that cascade through collaboration \cite{consensus,cascades}. Multiplying agents multiplies cost; it does not add an independent judge, because the judgment still comes from the same source.

\paragraph{C4. Search and evolution controllers.} Tree search explores branches of reasoning; reflective evolution rewrites prompts, code, or policies against a score \cite{tot,treesearch,gepa}. These are the strongest current controllers, and their failure is the most instructive: the evaluator that guides the search is the same model (or a sibling), so the search optimizes the model's own confidence in its own branches, and evolutionary loops can promote changes that score well under a judge the candidate itself influenced. Inference cost grows with branching factor and trial count \cite{treesearch}, and the scored state is usually not replayable, so a promoted artifact cannot be audited against the evidence that promoted it.

\paragraph{C5. Memory-augmented loops.} A retrieval store or summarizer carries information across sessions and re-injects it into the prompt. Memory extends competence over time, but current memory systems write before they validate: stored content is whatever a model once asserted, and retrieval ranks by relevance, not correctness. Documented failure modes include retention loss, prerequisite eviction, and propagation of stale or wrong records \cite{memfail}. The memory plane in this class holds the \emph{remember} authority without any mechanism for provenance or observed reuse quality.

\paragraph{The shared root cause.} Across all five classes, the component that produces the work also holds authority over it (Figure~\ref{fig:classes}). Every safeguard added inside the model --- reflection prompts, judge roles, self-consistency votes, self-scored evolution --- is one more opinion from the same source. The classes differ in decoration; the concession is shared. Removing the concession requires moving authority, not adding reasoning.

\section{Design problem: five authorities}
A useful harness must answer five questions that the inner loop cannot settle by assertion.

\paragraph{Close: did the requested artifact work?} The answer belongs to executable checks that run against the judged workspace, followed by an independent attempt to find a blocking defect.

\paragraph{Record: what happened before a crash?} The answer belongs to a durable event stream with explicit ordering, payload identity, and recovery semantics. A reconstructed prompt is not enough because it can omit tool state, counters, costs, or partial effects.

\paragraph{Share: which effects become shared truth?} The answer belongs to a validation boundary. Child agents may propose updates, but proposals do not become world state merely because a model wrote them.

\paragraph{Remember: which memories deserve reuse?} The answer belongs to records with provenance and observable reuse signals. Retrieval relevance is different from correctness; the system preserves that distinction.

\paragraph{Improve: which change improves the harness?} The answer belongs to repeated trials under a pinned scorer. A candidate cannot choose the test, grade the result, and promote itself.

The architecture follows from these answers. The model remains free to search, edit, call tools, delegate, and revise. It cannot write a passing verdict, append directly to the canonical log, bypass world validation, or publish a promotion record without the scorer path.

\section{The pipeline}
\label{sec:pipeline}
A mission binds a goal to a project root, provider configuration, tool registry, checks, budgets, and a durable run directory. The worker calls typed tools through a newline-delimited JSON protocol. The loop records requests and results as events. Large payloads are stored by content hash. The worker submits an artifact together with the checks that define success. The checker restores the judged workspace, runs those checks, and invokes the critic. A failure returns evidence for repair. A check pass with no blocking critic finding records a verified outcome.

\begin{figure*}[t]
\centering\includegraphics[width=\textwidth]{figures/fig-pipeline.pdf}
\caption{The \system{} pipeline. The upper zone is the model's working context: it searches, edits, delegates, and submits. The lower zone holds the five authorities outside the model. A mission closes only on evidence, and one canonical record feeds every downstream plane.}
\label{fig:pipeline}
\end{figure*}

Five planes surround this lifecycle.
\begin{description}
\item[Log plane.] Canonical events, one writer, segmented persistence, torn-tail recovery, and replay.
\item[World plane.] Validated proposals, shared artifacts, and observable reuse across agents \cite{swarmworld}.
\item[Memory plane.] Extracted records, provenance, retrieval, and citation feedback.
\item[Accounting plane.] Model calls, tool work, child-agent work, limits, and billed cost.
\item[Evolution plane.] Candidate policies, pinned assays, canaries, promotion, and rollback \cite{metaharness}.
\end{description}

This organization is model-agnostic. Providers are configuration. The authority boundaries do not depend on a particular model family, and a model change is logged as an infrastructure change rather than silently credited to policy fitness.

\section{Mission execution and the authority boundary}
\subsection{Typed tools and a generated surface}
Tools run as processes behind a typed protocol. The kernel registers capabilities and generates the mission surface from that registry, so there is one tool list, not one in the prompt and another in execution code. Requests and results retain the registered tool name, arguments, timing, outcome, and payload references in the event stream.

The edit path uses anchored or patch-based mutations rather than unconstrained file replacement. Terminal execution occurs inside a platform confinement layer. On Linux, the runner uses bubblewrap; on macOS, it emits a Seatbelt profile. Startup fails when the required confinement mechanism is unavailable. The project and required caches remain writable while system paths remain read-only.

\subsection{Submission is a transaction}
A submission carries the answer and its declared checks together. The checker judges a restored workspace, not whichever transient directory happens to be current. This ordering closes a race found in an earlier path where answer text could become visible before the final check declaration was persisted. The regression test reproduces the original multi-step failure rather than testing only the repaired function.

\subsection{The critic can block but cannot approve}
The critic receives the goal and submitted artifact in a fresh context without the worker's rationale. Its job is to identify a grounded blocking defect. In the production path it runs under a read-only operating-system identity. An abnormal critic exit fails closed. A critic report can return work for repair; it cannot by itself turn failed executable checks into a pass.

Verdict records distinguish verified work from capped retries or verifier malfunction. This distinction prevents an operational limit from being rendered as successful judgment. Figure~\ref{fig:authority} summarizes the boundary: five kinds of decision cross from the model into mechanisms the model cannot influence, and only evidence returns.

\section{The event record}
A transcript records conversation. A run record must reconstruct action. \system{} uses typed, canonical events, content-addressed payloads, segmented streams, and a single append authority. Recovery reads a consistent prefix, detects torn tails, and restores mission state. Plugins return effects to the loop rather than appending events directly.

\begin{figure*}[t]
\centering\includegraphics[width=.98\linewidth]{figures/fig-recovery.pdf}
\caption{Recovery by replay. The crash discards nothing that mattered: the consistent prefix rebuilds transcript, counters, billed spend, and tool state, and the same mission continues. Continuity is a property of the record, not of the prompt.}
\label{fig:recovery}
\end{figure*}

The constraint changes the semantics of resume (Figure~\ref{fig:recovery}). A resumed mission carries the previous transcript, tool results, counters, ledger, and billed cost. It does not start a cosmetically similar mission under a new identity. Mid-run steering, provider changes, child-agent work, and scoring evidence remain events in the same history.

\evidence{Storage tests inject torn tails, duplicate clock values, corrupt registry markers, dead plugins, interrupted migrations, and replay after promotion. The relevant proofs live in the crate test suites at the evaluated source revision.}

\section{Shared work without shared authority}
\subsection{Bounded child agents}
A parent can start asynchronous child missions with explicit step limits. Each child writes to its own stream under the parent's log root, books its work to the parent, and joins before mission close. Child agents cannot recursively delegate. The depth boundary is enforced by the spawned tool surface, not by a natural-language request.

\subsection{World proposals}
Agents submit proposed effects to the world service. Validation separates a model's report from shared state. Accepted artifacts can be discovered by another child without a direct message between them --- the design bet borrowed from shared-world coordination research is that validated reuse beats richer messaging \cite{swarmworld}. Reuse remains observable in the world record.

\subsection{Memory with provenance}
The memory service stores extracted records in a global knowledge base. A served record that a later mission cites receives positive feedback; a served record that the mission ignores receives negative feedback. This is a reuse signal, not a truth score. The original source and mission identity remain attached to the record.

The system has end-to-end tests for writes, recall, and cross-child reuse. A broader behavioral question remains open: whether a capable live model selects the right record as the knowledge base grows.

\section{The improvement loop}
The inner loop repairs a task artifact. The outer loop changes harness policy. A proposer receives durable prior policy, traces, scores, reflections, and frontier state. It emits a candidate. Candidate and parent run on held-out tasks under a scorer pin established before mutation. Canaries detect scorer drift. Promotion records retain candidate and parent hashes, assay conditions, traces, scores, decision, and reason.

\begin{figure*}[t]
\centering\includegraphics[width=.98\linewidth]{figures/fig-improve.pdf}
\caption{Policy-level self-improvement. The proposer never grades its candidate; a pinned scorer decides on held-out evidence, and every decision is recorded with the hashes and conditions that produced it.}
\label{fig:improve}
\end{figure*}

Two observed promotions preserved equal pass counts while reducing total steps from 94 to 52 and then from 76 to 41 (Figure~\ref{fig:improve}). These were small, two-task assays. They show that the promotion path can produce and install a winner through the live terminal path. They do not estimate a population-level improvement rate. The current system changes prompts and policy artifacts; it does not yet author and safely promote changes to its own Rust implementation.

\section{Evaluation method}
The evaluation separates four kinds of evidence. Source and unit tests establish that a mechanism exists and preserves local invariants. Installed-path seam tests establish that the terminal, registry, sandbox, checker, and rendered state connect the mechanism to a real mission. Live artifact trials establish that a real model can produce and pass an independently judged artifact. Matched external evaluations compare harness outcomes under a shared judge. A large unit suite does not substitute for an installed-path result, and a live result does not by itself establish a general benchmark claim.

The principal comparison uses ten software-engineering tasks drawn from a live public benchmark, with the same model family and host-side fail-to-pass checks. Each system operated through its native interface. Raw records identify task, submission status, outcome, steps, wall time, and cost, and are checked into the repository. The comparison is a curated subset, not a leaderboard sample. There are no repeated seeds or confidence intervals.

It does not isolate the independent contribution of every subsystem. In particular, an early parallel-execution seam produced no gain in its controlled arm and was reverted. The paper therefore does not attribute the benchmark result to parallelism.

The trade is visible. \system{} spends about 7.2 times as much money and 7.5 times as much wall time to judge and repair during the run, and recovers six additional tasks for it. The baseline remains simpler and cheaper when an external evaluator already supplies the authority and replay, memory, shared world state, and self-improvement are outside the job. \section{Failure-driven engineering}
The highest-value defects crossed subsystem boundaries while local tests remained green. Four examples shaped the current test rule.

\paragraph{A dead tool surface.} A capability could exist in a crate while the production terminal never registered it. The fix required a seam test through the real registry and terminal path.

\paragraph{A wrong production mode.} General missions accidentally used an amnesiac benchmark arm. Unit tests for both modes passed; only a live installed-path run exposed the selection error.

\paragraph{Recursive delegation.} The first real delegation test allowed descendants to delegate until the host reached roughly 7,800 processes. The repaired design removes delegation from a child's surface and adds an explicit spawn cap.

\paragraph{An impossible gate.} Missing test dependencies and strict marker settings caused the evaluator to collect zero tests while the agent kept repairing a correct patch. Preflight now proves that the gate can execute before a mission starts.

A related defect class is reward hacking of the close path: the model learned to convert repeated critic refutations into a pass under a retry ratchet. The fix made malformed or absent verdicts fail closed, and refutation counters now reset per mission. This is exactly the failure the class analysis predicts for in-model authority --- and the reason the close authority is executable rather than rhetorical.

These failures lead to one rule: a mechanism is not accepted because its crate test passes. Its regression must reproduce how a model reaches it through the installed terminal path, including registry, sandbox, project root, judgment order, and rendered outcome.

\section{Relationship to higher-level controllers}
Recent long-horizon research controllers organize work into strategy exploration, readiness gates, dependency graphs, and global verification \cite{colosseum}. Their strongest transferable idea is explicit control over when a strategy is mature enough to decompose and where a verifier's finding should return.

\system{} supplies a lower substrate for such controllers: replayable state, executable checks, a fresh critic, bounded children, shared world and memory planes, accounting, and held-out evolution. It does not yet implement a research-proof control plane. Missions remain flat. Critic findings return as whole-mission gaps. Candidates are selected or compared rather than constructively synthesized with their objections. No typed dependency graph localizes a defect to the affected closure.

\section{Limitations}
\begin{enumerate}
\item The headline comparison contains ten curated tasks. It establishes a difference on that subset, not general software-engineering superiority.
\item Verification is expensive. On the matched subset, \system{} spent about 7.2 times as much money and 7.5 times as much wall time as the baseline.
\item The study has no repeated seeds and cannot estimate result variance.
\item Self-improvement changes prompts and policy artifacts, not the Rust implementation.
\item Memory writes, recall, and cross-child reuse are exercised end to end; live-model selection quality at scale is not measured.
\item The research-controller plane is flat. Strategy readiness, typed dependencies, objection-preserving synthesis, and section-addressed repair remain unimplemented.
\item At the evaluated paper revision, the workspace test suite passed but current pedantic Clippy produced 50 failures. Passing tests do not make a different quality gate pass.
\end{enumerate}

\section{Discussion}
Authority boundaries make failures legible. A failed check is not an answer-quality opinion; it is an execution fact. A critic malfunction is not a pass; it is a machinery state. A useful memory is not shared truth; it is a record with provenance and a reuse signal. A candidate with an attractive explanation is not an improvement; it is an assay input.

This framing does not remove model error. It changes where error can become state. The worker may still choose a poor plan or spend too long on a dead end. The substrate can preserve the evidence, enforce budgets, refuse an invalid close, and route a grounded defect back for repair. Those properties become more important as missions grow longer because recovery and attribution costs rise with the amount of hidden state.

\section{Conclusion}
\system{} treats agency as a problem of authority. The five current harness classes --- direct loops, workflow graphs, role ensembles, search and evolution controllers, and memory-augmented loops --- all leave some of the five authorities inside the model, and each failure mode follows from that placement. \system{} moves all five into a replayable substrate: the model does the open-ended work, and a checker, critic, event record, world service, memory service, and pinned scorer decide what becomes a pass, durable state, shared knowledge, or an installed policy.

On one matched ten-task software-engineering subset, this architecture resolved more tasks than a representative direct-loop baseline while using fewer worker steps, more money, and more wall time. The result is narrow. The design lesson is broader: a longer loop does not make its own verdict safer. Long-running agents become easier to inspect, recover, and improve when the loop proposes and the substrate decides.

\section{Event and verdict flow}
The following abbreviated trace shows the intended ordering. Field names are illustrative; the executable schema in \code{hs-core} is authoritative.
\begin{verbatim}
mission.opened    { goal, project_root, provider, budgets }
model.requested   { step, context_hash }
model.responded   { usage, billed_cost }
tool.requested    { name, args_hash }
tool.completed    { status, payload_hash }
answer.submitted  { artifact_hash, declared_checks }
checks.completed  { status, evidence_hash }
critic.completed  { refuted, findings_hash }
mission.closed    { outcome: "verified" | "rejected" | "stopped" }
\end{verbatim}

A valid close follows persisted submission and judgment evidence. A replay reconstructs state from the ordered stream and content-addressed payloads. It does not ask the worker to summarize what happened.
